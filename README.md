# Мини-Склад — учебная конфигурация 1С:Предприятие 8.3

Учебный проект стажировки КБ99, курс «1С Старт с нуля», недели 1–2. Минимальный контур складского учёта: справочники товаров и контрагентов, документы поступления и реализации с движениями по регистрам, отчёт на СКД и печатная форма реализации.

Автор: Шляхтин Максим Дмитриевич.

## Что внутри

Каталог `src/cf` — конфигурация, выгруженная в XML-файлы (Конфигуратор → Конфигурация → «Выгрузить конфигурацию в файлы…»).

| Объект | Имя | Состав |
| --- | --- | --- |
| Подсистема | `Мини_Склад` («Мини-склад») | Все объекты ниже; включена в командный интерфейс, команды создания, списки регистров и отчёт выведены на панель |
| Справочник | `Товары` | Код, наименование |
| Справочник | `Контрагенты` | Код, наименование |
| Документ | `Поступление` | Реквизит `Контрагент`; табличная часть `Товары` (`Товар`, `Количество`); проведение — приход в `ОстаткиТоваров` |
| Документ | `Реализация` | Реквизит `Контрагент`; табличная часть `Товары` (`Товар`, `Количество`); проведение — расход из `ОстаткиТоваров` и запись в `ПродажиТоваров`; макет `ПечатьРеализации`, команда «Печать» на форме |
| Регистр накопления | `ОстаткиТоваров` («Остатки товаров») | Вид «Остатки»; измерение `Товар`, ресурс `Количество` |
| Регистр накопления | `ПродажиТоваров` («Продажи товаров») | Вид «Обороты»; измерения `Товар`, `Контрагент`, ресурс `Количество` |
| Отчёт | `ОборотыПоТоварам` («Обороты по товарам») | СКД на виртуальной таблице `ОстаткиТоваров.ОстаткиИОбороты`: начальный остаток, приход, расход, конечный остаток по товарам за период; период задаётся на форме отчёта |

Код проведения (`Documents/<документ>/Ext/ObjectModule.bsl`) построен конструктором движений, имена переменных приведены к кодстайлу (`ТекущаяСтрокаТовары`, `ДвижениеРегистра`, `ДвижениеПродаж`), переменные объявлены явно, модули оформлены областями. Печать реализации (`Documents/Реализация/Forms/ФормаДокумента/Ext/Form/Module.bsl`) собирает табличный документ из макета `ПечатьРеализации` по областям `Шапка`, `ШапкаТаблицы`, `Строка`, `Подвал`.

У реквизитов `Контрагент`, `Товар` и `Количество` обоих документов включена проверка заполнения («Выдавать ошибку»).

## Требования

- 1С:Предприятие 8.3.27 или новее (режим совместимости конфигурации — 8.3.27). Подходит версия для разработчиков.
- Управляемое приложение, тонкий клиент.

## Как открыть

1. Клонировать репозиторий:
   ```
   git clone https://github.com/mrekk-hub/kb99-1c-mini-sklad.git
   ```
2. В окне запуска 1С: «Добавить» → «Создание новой информационной базы» → «Создание информационной базы без конфигурации» → файловый вариант.
3. Открыть базу в конфигураторе → Конфигурация → «Открыть конфигурацию».
4. Конфигурация → «Загрузить конфигурацию из файлов…» → «Загрузить из: XML-файлы» → каталог `src/cf` → «Загрузить».
5. F7 («Обновить конфигурацию базы данных») → «Принять».
6. Запустить 1С:Предприятие → раздел «Мини-склад».

Пакетно, без открытия окна (путь к платформе подставить свой):

```
"C:\Program Files (x86)\1cv8\8.3.27.2342\bin\1cv8.exe" DESIGNER /F "<каталог базы>" /LoadConfigFromFiles "<путь к репозиторию>\src\cf" /UpdateDBCfg /Out "load.log"
```

## Как проверить

1. Создать два товара и одного контрагента.
2. Поступление 01.10.2026: Товар 1 — 10, Товар 2 — 5 → «Провести».
3. Реализация 05.10.2026: Товар 1 — 3, контрагент заполнен → «Провести».
4. Разделы «Остатки товаров» и «Продажи товаров»: приход и расход по каждой строке, продажа с контрагентом.
5. «Отчёты» → «Обороты по товарам» → период 01.10.2026 – 10.10.2026 → «Сформировать». Ожидается: Товар 1 — приход 10, расход 3, конечный остаток 7; Товар 2 — приход 5, конечный остаток 5.
6. Открыть проведённую реализацию → «Печать»: форма «Реализация № … от …», контрагент, строки товаров и итого по количеству.

## Как вносить изменения

1. Доработать конфигурацию в конфигураторе, F7.
2. Конфигурация → «Выгрузить конфигурацию в файлы…» → каталог `src/cf` этого репозитория.
3. `git status` → проверить изменения → коммит с префиксом: `feat:` — новая возможность, `fix:` — исправление, `refactor:` — переработка без изменения поведения, `docs:` — документация.

## Известные ограничения

- Проведение не контролирует остатки: реализация проводится и при нехватке товара.
- Печатная форма выводит количество без цены и сумм: в конфигурации нет цен.
